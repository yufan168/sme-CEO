# 設定清單：享洺每日營運摘要（四 Agent 接力，Level 0 僅內部使用）

> 產出時間：2026-08-02 06:35
> n8n 版本：1.x-stable　行業 Profile：general

## 需人工填入的佔位符

| 佔位符 | 節點名稱 | 說明 |
|--------|----------|------|
| `【請填入：享洺營運資料 API 網址】` | 收集營運資料 | 提供案件、收支、政府計畫與課程資料的 API 端點。目前享洺尚未接資料來源，這一欄未填流程不會有內容。 |
| `OPS_API_CRED_ID` | 收集營運資料 | 營運資料 API 的 Header Auth 憑證 ID。 |
| `OPENAI_CRED_ID` | 四個 Agent 節點 | OpenAI API 憑證 ID。若要改用與系統相同的 Anthropic，見設定清單的替換說明。 |
| `【請填入：寄件者信箱】` | 寄送給負責人、錯誤通知 | 寄件者信箱。享洺的正式聯絡方式在知識庫 COMPANY-004 仍是待填狀態，這裡不代填。 |
| `【請填入：負責人收件信箱】` | 寄送給負責人、錯誤通知 | 負責人收件信箱。Level 0 僅內部使用，收件人只能是負責人。 |
| `SMTP_CRED_ID` | 寄送給負責人、錯誤通知 | 寄信用 SMTP 憑證 ID。 |

## 匯入步驟

1. 下載 `workflow.json`
2. 進入 n8n → 左上角「＋」→「Import from File」→ 選取此 JSON
3. 工作流以**停用狀態**匯入，先完成以下設定再啟用
4. 依上表逐一設定 Credentials（在 n8n Settings → Credentials 新增）
5. 以手動觸發測試一次，確認各節點正常執行
6. 確認無誤後啟用排程

## 建議測試步驟

1. 匯入後以停用狀態確認節點結構與連線
2. 逐一填入 Credentials
3. 手動觸發沙盒測試（建議先用少量測試資料）
4. 確認各節點輸出符合預期
5. 確認無誤後啟用排程觸發

## 與享洺治理規則的對應

| 治理規則 | 這份工作流怎麼落實 |
|----------|-------------------|
| Level 0 僅內部使用 | 收件人只有負責人，全流程沒有任何對客戶發送的節點 |
| AI-003 不得自行建立公司事實 | 聯絡方式、服務時間、價格一律用【請填入】，不代填 |
| AI-004 不得自行承諾 | 四個 Agent 的 system prompt 都明寫不得產生報價、折扣、費用或交期 |
| AI-001 不得猜測 | 資料缺口寫成【資料缺口】【待確認】【待指派】【待負責人設定】，不補值 |
| AI-006 必須保留來源 | 組裝節點刻意不呼叫 AI，四段產出原文拼接，可回溯是哪一個 Agent 寫的 |
| 停止條件 | 任一節點失敗會觸發錯誤通知，信中明寫「今日沒有產生摘要，不要把這封信當成今日無異常」 |

四位 Agent 對應享洺現有編制，不是新角色：

| 節點 | 對應 Agent | 部門 | 工作邊界 |
|------|-----------|------|----------|
| S01 經營資料整理員 | S01 | 經營策略與決策部 | 只整理資料，不解釋公司應採取何種策略 |
| O01 待辦整理員 | O01 | 營運與財務管理部 | 不得虛構責任人，不得自行設定期限 |
| O03 期限與異常監測員 | O03 | 營運與財務管理部 | 不判定責任歸屬，不預告主管機關審查結果 |
| S02 方案比較分析員 | S02 | 經營策略與決策部 | 只能提出比較，不能替公司決定方向或預算 |

## 若要改用與系統相同的 Anthropic

系統的 AI 設定分頁同時支援 Anthropic 與 OpenAI。要讓 n8n 這條流程用同一個供應商，四個 Agent 節點各改三處：

1. `url` 改為 `https://api.anthropic.com/v1/messages`
2. `nodeCredentialType` 改為 `anthropicApi`
3. `jsonBody` 的結構改為 Anthropic 格式：`system` 獨立成一個欄位，`messages` 只放 user，並加上 `max_tokens`

同時「組裝每日營運摘要」節點的取值要由
`payload.choices[0].message.content` 改為 `payload.content[0].text`。

## 已知的一項驗證警告

`治理註記` 是 Sticky Note，本來就沒有連線，驗證器會報一項「孤兒節點」警告。這是預期的，不影響匯入與執行。

## 這條流程現在還跑不出東西

`收集營運資料` 指向的 API 尚未存在。享洺目前沒有把案件、收支與課程資料接成可查詢的端點，CEO 戰情室頁面上也明寫「營運數字尚未接入」。在資料來源接上之前，這條流程匯入 n8n 可以檢視結構、可以手動跑到失敗，但不會產出有內容的摘要。

要先看效果的話，可以把 `收集營運資料` 暫時換成一個回傳固定 JSON 的節點測試四個 Agent 的接力是否正常。
