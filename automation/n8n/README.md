# n8n 自動化流程

放享洺實際要匯入 n8n 的工作流。這裡的檔案不是網站的一部分，不會被 build 打包，
也不會出現在任何分頁上，純粹是可以下載匯入 n8n 的設定檔。

## 目前的流程

### 享洺每日營運摘要（四 Agent 接力）

| 項目 | 內容 |
| --- | --- |
| 檔案 | `享洺每日營運摘要-workflow.json` |
| 設定說明 | `設定清單.md` |
| 觸發 | 每日 08:30（cron `30 8 * * *`） |
| 審核等級 | Level 0 僅內部使用 |
| 收件人 | 只有負責人 |
| n8n 版本 | 1.x-stable |

四個 Agent 節點對應系統裡現有的編制，不是新角色：

| 節點 | Agent | 部門 |
| --- | --- | --- |
| S01 經營資料整理員 | S01 | 經營策略與決策部 |
| O01 待辦整理員 | O01 | 營運與財務管理部 |
| O03 期限與異常監測員 | O03 | 營運與財務管理部 |
| S02 方案比較分析員 | S02 | 經營策略與決策部 |

最後一段刻意不呼叫 AI：四位的產出由 Code 節點原文拼接。經過 AI 重寫之後就無法回溯
哪一句是哪一位寫的、有沒有被改動，這與 AI-006「必須保留來源」衝突。

**這條流程目前跑不出內容。** `收集營運資料` 指向的 API 尚未存在，享洺還沒有把案件、
收支與課程資料接成可查詢的端點。匯入 n8n 可以檢視結構、可以手動跑到失敗，但不會有摘要。
要先驗證四個 Agent 的接力，把該節點暫時換成回傳固定 JSON 的節點即可。

## 匯入方式

1. 下載 `享洺每日營運摘要-workflow.json`
2. n8n → 左上角「＋」→ Import from File
3. 依 `設定清單.md` 的佔位符表逐一填入憑證與信箱
4. 先手動觸發測試，確認無誤後再啟用排程

匯入後是停用狀態。所有 `【請填入：…】` 的欄位都必須先補齊，否則流程會直接失敗
（這是刻意的，未填的欄位不會被預設值蓋過去）。

## 重新產生

`build.py` 是這份 JSON 的來源。要改流程內容請改 `build.py` 再重新產生，
不要直接手改 JSON，避免節點改名後 `connections` 沒同步而產生斷鏈。

```
python3 build.py
python3 <skill>/scripts/validate_workflow.py 享洺每日營運摘要-workflow.json \
  --version 1.x-stable --industry general
```

`build.py` 需要 `n8n-workflow-generator` skill 的 `generate_workflow.py`，
路徑寫在檔案開頭的 `sys.path.insert`，換機器時要調整。

驗證預期結果：0 錯誤、1 項警告。該警告是治理註記那張 Sticky Note 沒有連線，
Sticky Note 本來就不接線，屬預期。
